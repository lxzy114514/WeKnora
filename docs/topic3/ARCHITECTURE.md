# 架构与数据设计

## 总体链路

```text
版本化数据集清单
      │ 校验路径、大小和 SHA-256
      ▼
DatasetService ──► EvaluationService ──► 真实 RAG / 模型适配器
                         │                         │
                         │ 状态、配置、逐题指标   │ 每次调用、价格、耗时、缓存
                         ▼                         ▼
                  EvaluationRepository      ModelCallRepository
                         │                         │
                         └─────────┬───────────────┘
                                   ▼
                 四类报告 + evalctl JSON/Markdown
                                   │
                                   ▼
                    evalgate 基线/阈值回归判断
```

这条链路把“测量”和“是否放行”分开：评测系统负责生成事实，门禁只执行审查过的比较政策。模型负责生成或排序；WeKnora 负责模型注册、调用、上下文关联、落库和循环控制。

## 深模块边界

### DatasetCatalog

`DatasetService.GetDatasetSnapshot` 把一个数据集 ID 解析成不可变快照。ID 只能是安全的目录名；清单声明版本、文件名、字节数和 SHA-256。运行前和真正执行前都会校验，避免排队后文件被替换。

### EvaluationRepository

数据库是历史结果的事实来源；进程内对象只服务于当前运行中的并发更新。启动时，遗留的 `Pending`/`Running` 会被标记为失败并写明重启原因，避免永久假运行。状态查询只返回运行摘要，逐题证据由独立端点分页读取；所有读写均携带租户条件。

### ModelTelemetry

模型对象通过装饰器记录一次逻辑调用，不把 GORM 依赖带入模型实现。记录内容只包含计数、耗时、结果状态、用途、关联 ID、价格快照和不可逆前缀指纹。普通请求优先使用显式关联 ID，否则回退到请求 ID 或会话 ID；评测统一用任务 ID。

### EmbeddingCache

键为：

```text
(tenant_id, model_id, dimensions, model_config_fingerprint, SHA256(text))
```

配置指纹覆盖模型名、来源和有效参数，但去除 API Key、App Secret 和价格。因此换租户、模型、提供商配置或维度必然失效，单纯轮换凭据/价格不会浪费可复用向量；修改或删除数据库模型配置时还会主动清除该模型的派生向量。数据库唯一约束保证跨进程写入幂等；进程内按内容键加锁并在获得锁后复查数据库，合并单条与重叠批次的并发未命中。批量请求只计算缺失项，并按原输入位置装回结果；命中统计失败不会把有效向量降级为上游调用。

### EvaluationGate

纯比较函数输入基线、当前报告和阈值。质量指标使用“越高越好”，成本和耗时使用“越低越好”。它会返回全部失败项；任一配置哈希为空、哈希不同、阈值为空或指标重复都会直接拒绝比较。

线上评测与 `evalbench` 不各自维护指标清单，而是共享同一个带稳定名称的注册表；新增或修改指标时，两条路径会同时变化，注册表测试还会拒绝重名。

## 数据库表

### `evaluation_runs`

保存任务状态、开始/结束时间、完整 Pipeline 参数、不可变配置快照、质量汇总、成本和耗时。配置快照包含数据集及各文件哈希、Chat/Embedding/Rerank/Summary 四种角色的模型 ID、去除凭据后的模型参数哈希与价格、来源知识库、分块大小/重叠、完整 Pipeline 参数哈希、代码版本和整体条件哈希。条件哈希不含代码版本，因为回归门禁本来就要比较不同代码版本；代码 SHA 仍单独保留以便追溯。

### `evaluation_cases`

按 `(task_id, qid)` 唯一，保存检索与重排命中的数据集 passage ID、最终答案、逐题检索/回答指标、错误和检索/重排/生成阶段耗时。QID 可回到版本化数据集取得问题与标准答案，因此这些字段足以复算汇总并定位回归。

### `model_calls`

保存五类模型的逻辑调用：

- Chat：厂商返回的输入、输出、缓存读写/未命中 token。
- Embedding：估算输入单位、条目数、缓存命中/未命中。
- Rerank：候选文档数。
- VLM：图片数和根据字符数估算的 token，明确标记为估算；数据库模型与旧版知识库内联配置都经过统一观测，后者使用不含凭据的稳定派生模型 ID。
- ASR：音频字节数、耗时和调用结果；当前没有按分钟计价字段，费用为零。

价格存为每次调用的快照，历史费用不会因后来修改模型价格而变化。普通未命中输入、缓存读取和缓存写入 Token 各自只按对应完整单价计算一次；缓存写入价格不是叠加在普通输入价上的溢价。当前管理界面统一按 USD 配置，Chat 与 VLLM 都可填写输入/输出价格。

### `embedding_cache`

只保存键、JSON 向量、命中数和访问时间，不保存原文。PostgreSQL 与 SQLite 都有对应迁移和唯一索引。

## 提示词缓存

普通 RAG 系统提示中，首次动态占位符（`contexts`、`query`、`current_time`）之前的内容定义为稳定前缀。实际发送给模型的提示词不变，只有观测指纹基于稳定部分计算，因此不会为了命中缓存改变问答语义。Wiki 路径继续复用已有稳定前缀和缓存观测逻辑。

## 安全与隐私

- `model_calls` 不记录实际提示词、回答正文或文档原文，也不记录 API Key/App Secret；评测配置只保存固定模板与去除凭据后的模型参数哈希。为满足质量复算，租户隔离的 `evaluation_cases` 会保存固定测试集的最终答案和 passage ID，不保存检索文档正文。
- 数据集 ID 拒绝路径穿越；清单哈希不匹配时停止评测。
- 模型用量、评测运行、逐题结果和向量缓存默认按租户隔离。
- API 输入的时间必须是 RFC3339，且结束时间不能早于开始时间。
- 缓存哈希用于寻址而非访问控制，租户 ID 仍是第一层隔离条件。
