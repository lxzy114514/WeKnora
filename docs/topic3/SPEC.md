# 课题三：评测、模型成本与缓存工程化规格

## 目标

在不改变 WeKnora 核心问答语义的前提下，把已有的临时评测和模型用量日志扩展成可复现、可查询、可回归拦截的工程闭环：

1. 固定数据集、模型和分块配置，评测运行及逐题结果持久化。
2. 单次运行同时产出检索准确性、回答质量、成本和耗时报告。
3. 提供可定时执行的 CI 回归门禁，指标下降时明确失败指标。
4. 每次 Chat、Embedding、Rerank、VLM、ASR 调用落库；模型页可按模型和时间查询调用量、缓存命中与成本。
5. 相同租户、相同模型、相同维度、相同文本的 Embedding 可复用，且不保存原文。
6. 稳定提示词位于动态上下文之前，并能用不可逆指纹观测提示词缓存效果。

## 已授权的设计边界

用户已授权本任务中的计划、技术方案、实现和测试由 Codex 自主决定。以下测试接缝视为本课题的固定设计约束：

- `DatasetCatalog`：把数据集名称解析为不可变清单和内容哈希；默认清单必须显式版本化。
- `EvaluationRepository`：按租户持久化运行生命周期、配置快照、聚合指标和逐题结果；进程重启后仍可查询。
- `ModelTelemetry`：模型适配器只上报一次结构化调用记录；计价、落库和聚合查询封装在仓库/服务内部，永不记录提示词或密钥。
- `EmbeddingCache`：键为租户、模型 ID、维度、有效模型配置指纹和文本 SHA-256；批量请求支持部分命中并保持输出顺序。
- `EvaluationGate`：纯函数比较基线、当前指标和阈值，返回全部失败项；命令行只负责文件输入输出和退出码。

## 数据模型

### 评测运行

持久化字段至少包含：任务 ID、租户 ID、数据集 ID、状态、开始/结束时间、总数/完成数、错误信息、参数快照、配置快照、聚合指标、成本报告和耗时报告。

配置快照至少包含：数据集版本与哈希、数据文件哈希、Chat/Embedding/Rerank/Summary 模型 ID、去除凭据后的模型参数哈希与价格、检索/生成 Pipeline 参数哈希、分块参数和代码版本。历史快照不可由后续模型配置变更反向修改。用于门禁的条件哈希不包含代码版本，使不同代码提交可以在相同实验条件下比较。

### 模型调用

每次逻辑模型调用保存：租户、模型 ID、模型类型、用途、关联 ID、提示词前缀指纹、令牌/条目计数、缓存读写/未命中计数、耗时、成功状态、错误类别、当次价格快照、估算成本和时间戳。

不得保存提示词、原始文档文本、API Key、App Secret 或提供商响应正文。

### Embedding 缓存

只保存去除凭据和价格后的模型配置指纹、SHA-256 文本哈希和向量；不同租户默认隔离。缓存写入采用唯一约束保证幂等，进程内并发未命中通过按键加锁合并。即使 YAML 在重启时复用同一模型 ID，提供商、地址、模型名或维度发生变化也不会读到旧向量。

## API 与兼容性

- 保留现有 `POST /api/v1/evaluation` 和 `GET /api/v1/evaluation?task_id=...`。
- 新增评测运行列表接口，查询始终受当前租户约束。
- 逐题证据通过带 `limit`/`offset` 的独立接口分页读取；状态轮询不携带答案正文，避免长任务重复传输形成平方级开销。
- 新增 `GET /api/v1/models/usage`，支持 `model_id`、`start_time`、`end_time`、`purpose` 筛选。
- 模型价格属于模型参数，所有价格均明确为“每百万 token”或“每千条文档”的配置值；未配置价格时调用量仍记录，成本为零并标记为估算值。

## 报告口径

- 检索报告沿用已有 Recall、MRR、NDCG、MAP 等指标。
- 回答质量沿用已有 BLEU、ROUGE、METEOR、Exact Match、F1 等指标。
- 成本报告来自评测关联 ID 下的模型调用记录，按模型类型和模型 ID 汇总。
- 耗时报告包含索引、检索、重排、生成、评测总耗时、平均逐题耗时及模型调用耗时。

## 回归门禁

门禁输入为两个 JSON 报告和阈值配置。两个报告都必须携带相同的非空配置哈希，策略至少包含一个指标且不能重复；缺少这些条件时直接失败，不能静默放行。默认方向：质量指标越高越好，成本与耗时越低越好。失败输出必须包含指标名、基线值、当前值、变化量和允许阈值，并以非零状态退出。

CI 提供 `pull_request`、定时和手动触发。仓库工作流能生成报告并运行门禁；是否真正阻止合并还需要仓库管理员把该检查设置为受保护分支的必需检查。

## 验收场景

1. 干净环境按运行手册执行一个命令，得到结构一致、配置哈希一致的评测报告。
2. 把当前报告中的 Recall 人为调低后，门禁失败且输出明确指出 Recall。
3. 重启服务后仍可查询历史评测；另一租户无法读取该运行。
4. 模型用量接口按模型和时间过滤，返回调用次数、缓存 token/条目和数据库估算成本。
5. 同一租户对相同文本连续 Embedding 时第二次命中；换模型、有效模型配置、维度或租户时不命中。
6. Wiki/普通问答的稳定提示词指纹不因动态上下文变化而变化，且日志与数据库均不出现原始提示词。

## 非目标与限制

- 八种文档解析器横向比较属于可选扩展，不阻塞本课题主验收。
- 本分支不自动修改远端仓库分支保护规则、不推送代码、不创建最终发布标签。
- 没有有效模型密钥时，只执行确定性的单元/集成测试和门禁演示，不伪造真实线上模型成本或质量实验数据。
